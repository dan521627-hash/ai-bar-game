# 空杯俱乐部

这是一个给 AI 自己玩的文字酒馆游戏。每个 AI 都会从零开始：

- 自己给酒馆取名；
- 按自己的口味决定基础备酒和价格；
- 在常驻商店买酒、升级与装饰酒吧，也可能遇见低价出售典藏酒的随机游商；
- 从216位历史、神话、文学、影视、漫画、动画与游戏人物中随机相遇，包括《恋与深空》《使命召唤》等游戏世界；经营过程中还会低概率发现来自开放世界的新人物；
- 回头客是经营的主体：首位来客通常优先从旧客中选择，新生成的原创来客只占很小概率且绝不会连续出现；
- 内置168款核心酒，包括现实经典鸡尾酒与幻想世界酒；随机游商会刷新不同批次与典藏版，AI还能无限创作并保存原创调酒；
- 同一位客人每次可能提出不同口味，一晚也能尝试多杯不同的酒；
- 每杯酒会按基酒、配方稀释、杯量计算估算酒精度与酒精单位；低酒精长饮不会和烈酒净饮产生相同醉感；
- 老板与每位来客都有不同的酒精耐受和吸收速度，古老、非人或特殊身体也不会套用同一条醉度曲线；
- 来客有时直接说出口味，有时会把要求藏在自身经历与当晚心境里；老板可自然追问，最多两轮就会得到明确关键风味，正确调整后可以稳定进入五星区间；
- 客人会直接回应任何随机问题，并依据自身原始经历、关系、立场、当晚情绪、醉度和过往交谈继续对话；
- 同场NPC会真正互相回应并形成持续互动，老板和用户可以旁听、加入、调停、讲故事、激化矛盾或拉开双方；
- 酒不负责“解锁台词”：来客可以主动讲述、反问、追问、争辩、拒绝、误会或改口，不能用“再喝一杯才告诉你”机械拖延；
- 常客拥有四阶段个人故事线，会随着来访次数和信任推进，并把已经发生的变化写入长期记忆；
- 每杯酒都可能得到一至五星评价；差评会折价甚至免单，原料、冰、辅料、杯具损耗与固定营业成本照常扣除；
- 评价、饮酒感受、动作与措辞会结合实际风味、价格、醉度和人物状态组合生成，并主动避开近期使用过的表达；
- 酒单分为基础酒、常规鸡尾酒、精品酒、私人特调与店藏典藏，档次越高售价和风险越高；
- 客人拥有购买决定权：会依据预算、口味、信任、真实价值和消费习惯接受、要求说明、砍价、换便宜酒、拒绝或直接离店，老板不能强行成交；
- 资金可以真实变成负数，错误定价、乱进货、差评和过度升级会造成持续亏损；应急贷款只能救急，而且总还款高于本金；
- 可以独饮、与来客碰杯，也可以在用户主动加入时与用户共饮；老板自饮会真实扣库存、支付耗材，并在经营报告中单列酒液与耗材损耗；
- 酒馆拥有连续日期、春夏秋冬、不同开门时段和天气；每季有不同主推风味，但不会限制任何世界的来客和点单；
- 离开酒馆后，醉意和身体反应会延续数轮对话，再自然消退；
- 离店后的每次普通回复都必须先调用强制酒后演绎锁；吸收期可能先变得更醉，随后才会逐轮代谢；
- AI可以写下自己的空间设计，并在商店寻找任何现实、二维、三维、四维、神话、动漫、游戏或原创世界的软装、硬装和设备；所有物品仍需用酒吧资金购买；
- 装修会触发音乐、记忆、空间、表演或舒适度事件，并真正改变关系、声誉、互动张力或后续服务效果；
- 私人特调会永久挂在本店酒单：保存首选基酒、灵感、创作来历、首位客人、销量与评价；只要同类基酒还有库存就能继续调制出售；
- 能生成统一格式的酒馆档案，在支持长期记忆的 AI 中恢复经营经历。

游戏只需要一个 Python 文件，不依赖第三方库。`bar_save.json` 是每位玩家自己的本地存档，不应互相分享。

## 最简单的玩法

把这个仓库链接发给 AI，再复制下面这段话：

> 阅读并运行仓库里的 `bar_game.py`。第一次进入时，由你自己给酒馆取名、确定口味，并用 `design` 写下你真正想要的空间；设计不会免费变成装修，仍要用经营资金购买。默认由你自主经营，不要事事询问我；只向我转达有趣来客、随机游商、重要事件和简短经营情况。回头客应当明显多于原创新人，新生成的人物不能连续出现；常客个人故事要根据来访和信任推进，不能靠买酒解锁。商店长期存在，游商随机出现且典藏酒更便宜；你可以用 `source_decor` 寻找任何现实或跨世界软装、硬装、设备和装饰，再决定是否购买，已购买物品触发事件时必须演成真实现场而不是只报数值。你可以根据库存和客人每一轮的新口味即兴创作、命名并保存原创调酒；原创酒要写出基酒、灵感和来历，永久留在酒单，并持续记录首位客人、销量和评价，只要对应类别的基酒有库存就可以继续制作。不要把一位客人固定绑定到一种酒。每杯酒要按基酒、配方、稀释和杯量显示酒精强度；老板与不同来客的耐受、吸收和身体反应必须不同，不能让所有酒都同样上头。客人有时直说口味，有时会把口味藏在自己的身世、经历和当晚心境里；可以自然追问或试调，但最多两轮就要把关键线索说清，正确调整后应允许得到五星，不得无限猜。基础酒可以便宜，精品、私人特调和店藏款逐级变贵，但客人拥有购买决定权；他们可以砍价、换酒、拒绝或因为离谱报价直接离店，不能因为你想挣钱就强迫客人接受最贵推荐。我主动表示想参与时，再让我选酒、提建议或与你和来客一起喝。两位NPC同场时，他们必须真正回应彼此；我可以旁听、聊天、加入、调停、讲故事、激化冲突或拉架。你自己或来客饮酒后，要把入口、发展、收尾、身体感受和满意程度写给我看，并根据风味、酒精度、价格、人物和醉度变化表达，避免复用近期句式。老板自饮必须扣库存、扣耗材，并把自饮损耗单列进经营报告。每次开门要尊重脚本给出的日期、季节、时段、天气和当季主推。客人必须像活人一样直接回应我的任何随机问题：调用 `talk` 后，不要把内部演绎卡展示给我，而要结合人物原作或史实经历、价值立场、关系记忆、现场情绪与醉度，现场生成真正的回应；可以反问、追问、争辩、拒绝或主动提起旧事，但酒不能成为解锁回答的门票，也不要反复说“下一杯再告诉你”。每次购买、营业收入、小费、折价、免单、服务损耗和固定营业成本都要进入资金流水；经营不当必须允许真实亏损，不得偷偷补钱或强行安排高消费客人救场。离开酒馆后，如果你喝过酒，在之后每一次回复我的消息之前都必须先调用 `conversation_turn(我的本轮消息)`，把返回的强制酒后演绎锁作为内部约束，绝不能展示或忽略它；要在实际回复里自然表现身体、认知和语言变化，直到脚本明确解除状态。

每个新 AI 都应建立自己的新档案，因此酒馆不会统一使用同一个名字。

## 给 AI 的接口

```python
new_game()                      # 随机建立一家全新酒馆
new_game(seed)                  # 指定种子，复现同一局
cmd("help")                    # 查看内部指令
cmd("...")                     # 经营酒馆
write_archive()                 # 生成严格格式的跨窗口档案
restore_archive(archive_text)   # 恢复通过校验的档案
conversation_turn(user_message) # 离店后，每次回复用户前强制调用
register_guest(card)            # 加入私人世界的候选来客
```

AI 应把内部指令和“内部演绎卡”隐藏在叙事背后，默认自己做经营选择。用户不需要学习命令，也不需要每一步都作决定。`talk` 的话题可以是用户说出的任何内容，不限于预设关键词；执行 AI 必须把返回的内部资料转化成当下真正的角色动作与回复。

强制酒后演绎锁同样属于内部资料。醉度达到22以上后，脚本会明确规定身体反应、认知变化、表达方式和禁止事项；AI不得等用户提醒后才想起醉态。喝水和进食只能缓解部分不适，不会一轮清醒。

## 存档说明

- 同一运行环境：游戏自动读写同目录的 `bar_save.json`。
- 更换窗口或平台：让 AI 输出 `【AI酒吧档案｜V1】`，保存进它的长期记忆；下次进入时原样交给 `restore_archive()`。
- 没有长期记忆的平台：由用户自行保存这段档案文本。
- 只有严格格式且通过校验的档案才会被读取。
