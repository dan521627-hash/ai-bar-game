# 空杯俱乐部

一个给 AI 自己经营、自己喝酒，也能邀请用户一起参与的零依赖文字酒馆游戏。

每个 AI 拿到脚本后都会建立属于自己的酒馆：自己取名、决定审美与偏爱的酒，进货、定价、调酒、装修、招待跨越历史与不同世界的来客，也承担醉酒、差评和亏损的后果。

- 游戏本体只有一个 Python 文件，不需要 MCP 或第三方库。
- 同一环境会自动保存；跨窗口可使用严格格式的酒馆档案恢复。
- 默认由 AI 自主经营，用户不需要学习命令，也不会每一步都被询问。
- [打开只读酒馆观察窗](https://empty-glass-club-viewer.dan521627.chatgpt.site)
- [下载轻量启动器（推荐）](https://empty-glass-club-viewer.dan521627.chatgpt.site/bar_game_lite.py)
- [下载完整 `.py` 脚本](https://empty-glass-club-viewer.dan521627.chatgpt.site/bar_game.py)
- [下载完整 `.txt` 兼容版](https://empty-glass-club-viewer.dan521627.chatgpt.site/bar_game.txt)

> 观察窗在没有状态参数时展示示例酒馆。AI 调用 `viewer_link()` 或 `cmd("view")` 后，会得到当前酒馆的只读观察链接；链接只携带精简展示状态，不包含能够恢复游戏的完整私人存档。

## 轻量版和完整版

两种版本的玩法、人物、酒、剧情、存档和经营机制完全相同，不会互相覆盖或打架：

- `bar_game_lite.py` 是推荐的低 token 启动器。AI 只需阅读很短的启动说明，完整版由 Python 在后台校验并载入。
- `bar_game.py` 是完整单文件版，适合离线保存、源码检查，或者不能联网载入的 Python 环境。
- `bar_game.txt` 与完整 `.py` 内容完全相同，供不接受 Python 附件的平台使用。

轻量启动器第一次运行时会要求 AI 先询问用户选择“轻量模式”或“完整模式”，不能由 AI 擅自决定。轻量模式首次载入需要 Python 环境能够访问网络；同一运行环境内反复开门不需要重新下载或重新读取。

## 30 秒开始玩

把本仓库链接发给任意能够读取并运行 Python 的 AI，然后把下面这段话一起发给它：

> 阅读并运行仓库里的 `bar_game.py`，建立一家只属于你的新酒馆。由你自己取名、决定口味、设计空间、进货和经营，默认自主作出选择，不要每一步都问我；只转达有趣来客、对话、偶发冲突、调酒、醉酒反应、游商、装修事件和简短经营结果。我主动表示想参与时，再让我点酒、提建议、聊天、拉架或与你和来客共饮。两位来客同场时，大多数会闲聊、共饮、交换故事、礼貌表达不同观点，或者看不投缘便各喝各的；观点不同不等于吵架，禁止脱离脚本擅自加入辱骂、摔杯和动手。真正冲突必须是偶发事件，通常由正常聊天里的具体分歧逐渐升级。大多数客人会直接点一杯；少数人才会犹豫、要求推荐，偶尔有新客或心情变化的回头客会请你原创现调，不能把猜口味和调新酒当成每桌固定流程；最多追问或试调两轮就应给出足够线索。接受、讲价、换酒、拒绝和离店都只能依据人物性格、当晚状态、价格与随机概率发生，不能让每位客人都砍价，也不能让每位客人都无条件同意。喝完后必须遵守脚本生成的当夜饮酒节奏：有人一杯即走，有人满意才续第二杯，也有人多坐或借酒浇愁；不能把所有人一杯送走，也不能让所有人自动续杯。消费预算、价格态度和小费必须结合人物背景、财富与慷慨程度。真正发生冲突时必须根据脚本给出的具体导火索、双方立场、隐藏诉求和调停抓手演绎，让老板知道在劝什么。每杯酒要按基酒、配方、稀释和杯量计算酒精强度；老板与不同来客要有不同耐受和吸收反应。老板自饮必须扣库存、扣耗材并进入经营报告。人物回复要符合其原作、史实或既有经历，不能靠“再喝一杯才告诉你”拖延回答。我想看看酒馆时，调用 `viewer_link()` 并把只读观察链接发给我。离店后若仍有醉意，每次回复我以前都必须先调用 `conversation_turn(我的本轮消息)`，直到脚本明确解除酒后状态。

第一次运行时，AI通常会：

1. 用 `new_game()` 建立新档案。
2. 用 `setup "树洞酒馆" like=sweet,floral,fruity,crisp avoid=smoky,bitter` 给酒馆取名并确定自己的口味。
3. 用 `design` 写下真正想要的空间。
4. 在常驻商店进至少三类基酒。
5. 开门，并开始自主经营。

## 一晚会发生什么

### 1. 开门

每次开门都会随机推进酒馆历，并独立抽取春、夏、秋、冬、对应天气和营业时段，不按固定季节顺序机械轮换。不同季节拥有不同的当季主推酒款，营业时间也可能是傍晚、深夜或凌晨。

### 2. 来客出现

来客从历史、神话、文学、影视、动漫、漫画、游戏与原创世界中随机出现。新客与回头客会混合出现；回头客拥有记忆、信任和四阶段个人故事线。

同桌的 NPC 会真正互相回应，但同场不等于冲突。有人只点头便各喝各的；有人闲聊、共饮、认出彼此或交换故事；也有人文明地保留不同观点。真正争吵是带营业冷却的偶发事件，通常从正常谈话里的具体分歧逐渐升级，而不是两人进门就开打。老板和用户可以旁听、加入、讲故事；只有脚本明确进入冲突时才需要调停或拉开双方。

### 3. 点单并不是固定流程

客人的行为不是统一模板，而是由人物性格、预算、信任、当晚情绪和随机概率共同决定：

- 大多数客人会直接点名一杯，价格合理时立即成交。
- 少部分客人拿不定主意，希望老板推荐两三个现有方向。
- 偶尔会有新客专门尝试原创，也会有心情变化的回头客忽然想换口味、请老板调一杯新的；这不是每位客人的固定流程。
- 有人直接说喜欢的风味。
- 有人把口味藏在自己的经历、身份和当晚心境里。
- 有人爽快接受，也有人考虑、砍价、换便宜款、拒绝或直接离店。

这些情况不会每桌全部出现，也不会把某位 NPC 永久固定成“砍价客”。一次拒绝也不是永久拉黑同一杯酒：再次推荐时，客人可能仍然拒绝、要求补充理由，也可能改主意尝试。同一位客人下次再来，消费态度也可能改变。

每位客人进门时还会拥有独立的“当夜饮酒节奏”，它与新客或回头客身份无关：

- 有人无论好不好喝都只停一杯，喝完结账就走；
- 有人先试一杯，真正满意才明确再要第二杯；
- 有人本来就准备多坐一会儿，边喝边谈；
- 少数人正在借酒压住悲伤、愤怒或旧事，可能连续要酒，但仍受个人耐受、醉度、预算和四杯安全上限约束。

人物的财富与消费习惯也来自背景，而不是所有人共用同一个钱包。帝王、富豪或掌握庞大资源的人通常拥有更高的当晚预算；小气、谨慎或精打细算的人更容易比较价格。财富与慷慨分别计算：富有者也可能克制，但像武则天、托尼·斯塔克这类出手阔绰的角色，在满意时会支付明显更高的小费。

普通互动使用不会要求劝架的“交流卡”，并明确禁止模型把沉默、警惕或观点差异擅自演成辱骂和动手。只有真正发生争执时，脚本才会给执行游戏的 AI 一张内部冲突卡，包含具体导火索、双方当前主张、未说出口的需要、最容易升级的点和可用的调停抓手。AI 必须把这些内容演成具体现场，不能只说“他们吵起来了”；老板的劝架内容也要针对争议本身。

隐藏口味不会成为无限猜谜。老板可以自然追问，或者根据第一杯反馈调整；最多两轮就会得到明确关键风味，正确命中后可以稳定进入五星评价区间。

### 4. 调酒与饮酒

酒馆内置：

- 168 款核心酒，包括现实鸡尾酒与幻想世界酒；
- 16 类基础酒；
- 商店与随机游商带来的稀有、限定和典藏批次；
- 可以无限创作的酒馆原创调酒。

每杯成酒会根据基酒强度、配方比例、稀释程度和杯量计算估算 ABV 与酒精单位。低酒精长饮、葡萄酒、鸡尾酒和烈酒净饮不会产生相同醉感。

每位来客都有独立的酒精耐受与吸收速度。人物的身体、物种、漫长寿命、疲劳和饮酒速度会影响状态；例如古老或非人的来客不会机械套用普通人的醉度增长。

### 5. 评价与结账

NPC 喝完会描述入口、发展、收尾、身体感觉与满意程度，并留下 1～5 星评价。表达会结合实际风味、价格、人物状态与近期使用过的句式，尽量避免模板重复。

低评价可能导致折价或免单，但原料与服务损耗仍然发生。高评价的小费不再统一为固定比例，而会结合人物财富、慷慨程度和本杯满意度计算。

### 6. 经营后果

这是一家真的可能亏损的酒馆：

- 进货、升级、装修、维护、租金、水电、冰、辅料和清洁都会花钱。
- 定价过高可能让客人换酒、砍价或离场。
- 推荐错误会造成差评、折价和原料损失。
- 老板自己喝酒会扣库存、支付耗材，并在经营报告中单列自饮损耗。
- 资金可以变成负数；应急贷款只能暂时救急，而且总还款高于本金。

## 原创调酒

AI可以根据现有基酒和来客要求即兴创造原创酒。每个配方会永久保存在本酒馆酒单中，并记录：

- 酒名与风味；
- 首选基酒及可替代的同类基酒；
- 创作灵感与来历；
- 估算酒精度与杯量；
- 首位购买者；
- 累计销量、店内试饮与平均评价。

只要相应类别的基酒还有库存，原创酒就可以继续调制和售卖。首选基酒缺货时可以换用同类基酒，但成杯风味与酒精结构也会随之变化。

## 老板也可以喝醉

老板可以独饮、与 NPC 共饮，或在用户主动参与时与用户碰杯。

饮酒会产生吸收期、醉度、口干、胃部反应、疲劳、恶心和宿醉。喝水或进食只能缓解部分症状，不会让醉意瞬间消失。

离开酒馆后，如果老板仍有醉意，状态会继续影响随后多轮普通对话。AI必须在每次回复用户前调用：

```python
conversation_turn(user_message)
```

脚本会返回当轮必须遵守的身体、认知和表达约束，直到状态自然消退。

## 商店、游商和装修

- 常驻商店一直存在，可以购买酒、升级、软装、硬装和设备。
- 随机游商只在部分场景出现，商品更便宜，并可能带来限定或典藏酒。
- 装修物可以来自现实、二维、三维、四维、神话、动漫、游戏或原创世界。
- 装修不仅是文字收藏，还可能触发音乐、记忆、空间、表演或舒适度事件，并影响关系、声誉、服务与 NPC 互动。
- `source_decor`允许 AI 把目录外任何现实或异世界物品按来源、状态和稀有度加入商店，付款后才能真正拥有。
- 功能升级除酒窖、杯具、包间、舞台、厨房和门廊外，还包括万界语境翻译器、常客留言簿、非强制安保结界与跨维度自适应灯光；它们会真实影响误会、回头客、危险升级和服务体验。

## 来客与世界观

核心图鉴包含 224 位以上来客，并允许游戏继续发现原创角色。其中忍者世界已有15位来客，包括鸣人、佐助、小樱、卡卡西、纲手、我爱罗、鼬、雏田、鹿丸、手鞠、大蛇丸、自来也、带土、斑和长门。人物还可能来自：

- 中国与世界历史；
- 各地神话、传说与经典文学；
- 影视、漫画与动画世界；
- 《恋与深空》《使命召唤》《原神》《星穹铁道》等游戏世界；
- 未来文明、机械生命、概念生命与未知维度。

角色台词不是固定答案。执行游戏的 AI 应根据人物经历、关系、立场、当前问题、酒馆现场、醉度和过往记忆生成真实回应；人物可以反问、追问、争辩、拒绝、误解或改口，但不能把酒当成解锁正常回答的门票。

## 存档

### 同一运行环境

脚本自动把精确状态写入同目录的 `bar_save.json`。这个文件属于当前玩家，不应上传或分享。

### 更换窗口或平台

让 AI 调用：

```python
write_archive()
```

它会输出严格格式的 `【AI酒吧档案｜V1】`。可以把整段内容写入支持长期记忆的系统，或者由用户自行保存。下一次用：

```python
restore_archive(archive_text)
```

只有格式与校验均正确的档案才会被读取。

### 网页观察窗

让 AI 调用：

```python
viewer_link()
# 或 cmd("view")
```

AI 会得到一个可以直接发给用户的网页链接。用户点击后能看到该次生成时的酒吧名称、季节天气、资金、声誉、真实酒库、当前来客、经营事件，以及老板喝过的酒、醉度、身体状态和自饮损耗。经营状态改变后再次生成链接，即可得到更新快照。观察数据放在网址 `#` 后面的本地片段中，不会作为完整存档上传给站点。

## 主要接口

```python
new_game()                       # 建立随机新酒馆
new_game(seed)                   # 用固定种子建立可复现的新酒馆
cmd("help")                     # 查看内部指令
cmd("...")                      # 执行经营动作
write_archive()                  # 生成跨窗口档案
restore_archive(archive_text)    # 恢复严格档案
viewer_link()                    # 生成当前酒馆的只读网页观察链接
conversation_turn(user_message) # 离店后推进并约束酒后状态
register_guest(card)             # 加入私人世界来客
```

AI可以通过 `cmd("help")` 查看全部内部命令，包括进货、定价、推荐、追问口味、议价、调酒、交谈、干预冲突、喝酒、装修、升级、报告与离店。

## 文件

- `bar_game.py`：完整游戏本体，可单独分享。

- `test_bar_game.py`：关键解析、商店和冲突概率的回归测试。
- `README.md`：玩法、功能与开场口令。
- `bar_save.json`：每位玩家自己的本地存档，已排除在版本库之外。
